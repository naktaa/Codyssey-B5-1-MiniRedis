# 모델 사용 정책

> 이번 Mini Redis 미션은 단일 PM 세션에서 운영하며 하위 에이전트를 호출하지 않습니다. 아래 Implementer·Reviewer 기본값과 위임 설정 절은 템플릿 참고용으로만 유지합니다. PM은 학습 코치, Reviewer는 요청 시 같은 세션의 검토 관점입니다. 실제 런타임 모델·Reasoning·속도는 별도 확인 전까지 미확인이며 이 chore에서 설정을 변경하지 않습니다.

사용량을 관리하기 위한 기본 운영 정책입니다. 실제 지원 모델·reasoning·속도 설정은 실행 환경에서 확인하며 성능이나 절감률을 보장하지 않습니다.

| 역할 | 기본 모델 | Reasoning | 책임 |
| --- | --- | --- | --- |
| PM | GPT-6 Sol | Medium | Step·TASK·승인·Review Decision·Triage·상태 관리 |
| Implementer | GPT-6 Sol | Medium | 분석 계획·승인된 구현·self-check·학습 노트 |
| Reviewer | GPT-6 Sol | Medium | 독립 검토·Findings |

- 전 역할 Medium이 기본이다. HIGH 난이도나 REQUIRED 리뷰라는 이유만으로 자동 High를 사용하지 않는다. 모델·reasoning과 Review 등급은 별개다.
- 문구·작은 CSS·단순 문서 수정처럼 영향이 명확하면 PM이 Sol Low를 선택하고 TASK에 짧게 이유를 남길 수 있다. 일반 구현과 리뷰는 Medium을 유지한다.
- 복잡한 설계·원인 불명 bug·중요 데이터/메모리 위험으로 Medium 분석에 구체적 한계가 있으면 해당 작업의 Sol High를 이유와 함께 제안한다. 사용자 승인 후 적용하고 범위가 끝나면 기본값으로 돌아간다.
- Astra·6.1 Sol·Luna 등 다른 모델로 전환하려면 사용자와 정책 변경을 합의한다. 사용자가 현재 세션에 별도 설정을 명시했다면 그 설정을 우선하고 실제 값과 이유를 기록한다.
- PM 세션은 유지한다. 위임 전에 하위 모델과 reasoning을 명시하고 실제 클라이언트가 제공하는 설정·실행 정보로 확인한다. 설정 누락으로 PM의 High 등이 상속되지 않게 한다. 확인 불가면 미확인이라고 알리며 에이전트의 자기소개만으로 설정을 검증했다고 하지 않는다.
- 기존 에이전트 설정이 우선 적용되는지 확인한다. 문서·위임 프롬프트만 바꿔 런타임 설정까지 바뀌었다고 주장하지 않는다. 지원하지 않는 모델 ID·설정 키는 만들지 않는다.
- 속도는 Standard를 기본으로 확인한다. 기존 명시적 속도 선택이 있으면 임의 변경하지 않고 사용량과의 관계를 안내한다. GPT-6이 6.1보다 항상 저렴하다거나 토큰 합계가 구독 한도 차감과 같다고 단정하지 않는다.

모델을 낮추기 전에 [WORKFLOW.md](WORKFLOW.md)의 사용량 관리 기준으로 반복 호출·불필요한 입력·중복 출력을 줄인다. PM이 모델을 선택하는 판단 자체를 매 턴 길게 반복하지 않는다.
