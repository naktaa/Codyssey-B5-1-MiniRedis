## Optional — 원문이 허용한 구현 선택

별도의 선택 기능 목록은 없습니다. 다음은 필수 기능을 만족하는 방법의 선택이며 추가 필수 과제가 아닙니다.

- 체이닝에서 이중 연결 리스트 재사용은 권장입니다.
- TTL 힙의 lazy deletion 등 관리 전략은 구현 선택입니다. 실제 삭제·만료 처리의 원문 의미를 만족해야 합니다.
- EXPIRE의 0 이하 초는 즉시 만료 처리해도 됩니다.
- KEYS 순서·정렬은 요구하지 않으며 빈 목록은 (empty array) 등으로 표현할 수 있습니다.
- 값 파싱은 원문의 최소 허용 방식 중 선택합니다.

## 사용자 추가 학습·운영 조건 — 원문과 구분

- C 연결 리스트 → 체이닝 해시맵 → 최소 힙 → LRU·TTL·메모리 제한 결합을 실습한 뒤 Python 최종 구현으로 포팅합니다. C는 선행 학습이며 최종 제출 환경은 원문의 Python입니다.
- C++는 사용하지 않고 [c-practice](../../c-practice/)와 [python](../../python/) 위치를 분리합니다. C 전체 CLI·10개 명령 구현을 별도 필수 결과물로 요구하지 않습니다.
- Python에서 heapq로 핵심 힙을 대체하지 않습니다. dict/set/collections 금지는 원문에도 있으며 heapq 명시는 사용자 추가 조건입니다.
- 사용자가 코드 설계·구현·테스트·디버깅·통합 테스트를 직접 수행합니다. PM은 단일 세션에서 질문·힌트를 제공하며 위임·자동 리뷰·별도 평가·요청하지 않은 완성 코드/직접 수정을 하지 않습니다.
- 이번 초기 chore는 원문·기존 Harness 정리·완료 기준·학습 계획·상태·빈 디렉터리·최소 설정까지만 허용합니다. 소스·함수 스켈레톤·테스트 코드는 생성하지 않습니다.

## Notes — 결정이 필요한 항목과 완료 기록

- 미명시 항목: 전체 조회(DBSIZE/KEYS)의 만료 정리 범위, TTL 남은 초의 반올림/절삭·시간 기준, 제한을 낮출 때 제거 시점, OOM 덮어쓰기 실패 시 기존 값 처리. 사용자 설계 시 원문을 우선하여 판단하고 필요한 결정을 [WORKLOG.md](WORKLOG.md)에 남깁니다.
- Python 저장소는 원문이 허용한 고정 길이 배열/인덱스 접근 수준에서 선택합니다. 배열 공간 관리가 필요하다는 이유로 동적 배열 보너스 전체를 필수로 승격하지 않습니다.
- 원문 8절은 참고 예시이며 유일한 테스트·출력 순서를 뜻하지 않습니다. 메모리 예시는 총 33바이트에서 user:1의 11바이트 제거 후 22바이트로 공식과 일치합니다.
- 구현만 끝나면 `구현됨 · 사용자 검증 대기`로 표시합니다. 완료는 사용자의 실제 결과·설명 근거로 갱신하며 정적 읽기·문서 작성·미실행 예상 결과를 테스트 성공으로 기록하지 않습니다.
- 리뷰를 요청하지 않았다는 이유로 필수 미완료로 처리하지 않습니다. 보너스 미선택과 필수 미완료도 구분합니다.
