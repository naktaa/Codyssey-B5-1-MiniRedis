# Harness v1 운영 — Mini Redis 학습형 적용

## 목적과 역할

이번 미션은 [AGENTS.md](../../AGENTS.md)의 학습 규칙에 따라 같은 PM 단일 세션에서 진행합니다. 기존 Harness 파일과 템플릿은 보존하되 자동 구현·위임·필수 리뷰·별도 평가 절차는 사용하지 않습니다.

| 역할 | 담당 | 변경 권한 |
| --- | --- | --- |
| 사용자 | 세부 설계·구현·테스트·디버깅·다음 단계 결정 | 핵심 소스·테스트 |
| PM | 학습 코칭·요청받은 설명/힌트·진행 기록 | 초기 설정·문서. 명시 요청 없는 핵심 소스 수정 금지 |
| Reviewer 관점 | 사용자 요청 시 같은 세션에서 정적 검토 | 검토 결과만 제공. source 수정·테스트 실행 금지 |
| Implementer | 이번 미션 비활성 | 자동 구현·수정·분석 위임 없음 |

기본 모델 정책은 [MODEL_POLICY.md](MODEL_POLICY.md)에 남깁니다. 문서 정책과 실제 런타임 설정은 구분하며 별도 API·runner·worktree·Test/Verifier Agent·Skill을 추가하지 않습니다.

## 한 단계 진행 순서

1. [README.md](../../README.md)의 학습 순서와 [REQUIREMENTS.md](REQUIREMENTS.md)에서 이번 단계의 목표·완료 기준을 확인합니다.
2. 사용자가 세부 자료구조·인터페이스·구현 방식을 설계합니다. PM은 질문이 있을 때 원리와 힌트를 제공합니다.
3. 사용자가 구현하고 직접 테스트·디버깅합니다. PM은 실행하지 않습니다.
4. 사용자가 요청한 경우에만 같은 세션에서 리뷰합니다. 검토는 오류 원인·반례·복잡도·개선 방향을 설명하며 자동 수정하지 않습니다.
5. 사용자 결과를 바탕으로 현재 단계·테스트 근거·남은 질문을 간결히 기록합니다. 구현·사용자 검증·사용자가 설명한 이해 상태를 구분합니다.
6. 다음 단계는 사용자의 의사에 따라 진행합니다. 자동 리뷰·별도 평가·다음 단계 자동 시작을 하지 않습니다.

## 기능 단위 단계

기존 TASK 템플릿은 보존하되 단계마다 TASK 작성·계획 승인·에이전트 인계를 요구하지 않습니다. 학습 계획은 README, 상태는 STATUS, 충족 여부는 REQUIREMENTS에서 관리합니다.
PM은 목표·경계·관찰 가능한 결과를 설명하고 How는 사용자에게 남깁니다. 필수 메서드 등 원문에 명시된 제약은 유지하되 노드 상세·함수 시그니처·호출 순서를 미리 고정하지 않습니다.

## Review 판단 기준

Review Decision 기록은 초기 chore 및 요청받은 검토의 상태를 설명하는 용도입니다. 단계 완료마다 코드 리뷰를 시작하거나 선택 질문을 강제하지 않습니다.

| 결정 | 이번 미션 적용 |
| --- | --- |
| SKIP | 리뷰 미요청 또는 문서·초기 설정만 변경. 별도 리뷰·평가 없이 진행 |
| RECOMMENDED | 사용자가 검토 필요성을 물었을 때 이유와 선택지를 설명. 요청 전에는 실행하지 않음 |
| REQUIRED | 자동 강제하지 않음. 사용자가 특정 검토를 필수로 요청한 범위에서만 사용 |

중요 안전 위험을 발견하면 원인·영향·대안을 알리고 미확인을 남깁니다. 등급을 이유로 에이전트를 호출하거나 source를 수정하지 않습니다. 이번 초기 chore는 SKIP입니다.

## 안전성 검토 기준

정적 읽기와 사용자 질문·요청 리뷰에서 실제 관련 위험만 다룹니다. 정적 확인만으로 실행 성공이나 안전을 보증하지 않습니다.

- **File Safety / Data Integrity**: 수정 전 원본 확인, source·생성물·사용자 데이터 구분, overwrite 이유·영향, 관련 없는 삭제·초기화 금지, 임시 파일 충돌·실패 중 원본 보존, encoding·newline·path·binary 보존.
- **C Memory Safety**: null/dangling/uninitialized pointer, 배열·버퍼 경계, use-after-free, double free, leak, ownership/lifetime, 포인터 연산과 할당 실패·해제 누락. 포인터·malloc/free 학습을 우회하지 않으며 과도한 방어 계층도 추가하지 않습니다.
- **Python**: mutable shared state, 예상 밖 None·type, 자료구조 간 참조·만료 상태의 일관성. 내장 자료형으로 핵심 알고리즘을 대체하지 않습니다.
- **Destructive Operation Safety / Secret/Credential Safety**: [AGENTS.md](../../AGENTS.md)의 명시적 요청·영향 확인·secret 비노출 규칙을 따릅니다. 사용자 테스트에는 별도 예제·임시 데이터를 우선합니다.

예상 밖 데이터 손실·큰 덮어쓰기·호환성·메모리 위험·범위 확대·구조 충돌이 생기면 위험 / 영향 / 대안 / 권장을 설명합니다. 에이전트가 임의 수정하지 않고 변경 요청·승인을 기다립니다.

## 승인 경계

이번 사용자 요청은 원문 보존·학습형 Harness 정리·요구사항/계획/상태 문서·빈 디렉터리·최소 설정에 대한 초기 chore 승인입니다. 핵심 소스·함수 스켈레톤·테스트 구현은 포함하지 않습니다.
이후 에이전트의 source·테스트·dependency·실행 설정 변경은 명시적인 직접 요청과 구체적 계획 승인이 모두 필요합니다. 질문·단계 완료·리뷰 요청·ACCEPT는 수정 승인이 아닙니다. 이미 승인된 범위의 초기 문서·설정마다 재승인을 요구하지 않습니다.
사용자가 직접 설계·구현하는 데 에이전트용 승인 절차를 요구하지 않습니다.

## 위임과 결과 회수

이번 미션에서는 사용하지 않습니다. Implementer·Reviewer·Test/Verifier Agent를 호출하지 않으며 수동 인계나 새 세션 생성도 요구하지 않습니다. 기존 역할·TASK·리뷰·학습 템플릿은 참고용으로 보존합니다.
사용자가 명시적으로 요청한 완성 코드·직접 수정 예외도 같은 세션의 승인 범위에서만 처리하며 자동 위임으로 전환하지 않습니다.

## 사용량 관리

### PM 세션 유지와 맥락 관리

같은 PM 세션을 유지하며 실제 지원되는 요약과 짧은 STATUS로 복구합니다. 단계 완료·맥락 누적을 이유로 새 PM을 요구하거나 기록을 삭제하지 않습니다.

### 읽기와 도구 사용

최초 원문은 전체를 확인합니다. 후속 요청은 유효한 맥락을 재사용하고 rg로 필요한 파일·구간·변경을 찾습니다. 관련 근거·안전 검토는 빠뜨리지 않되 전체 문서·로그를 반복 출력하지 않습니다. 독립 읽기는 묶고 의존하는 편집은 순서대로 진행합니다.

### 코칭과 요청 리뷰의 경계

오류 원인·개념 질문에는 필요한 근거를 읽어 답하고 미요청 전체 코드 리뷰·별도 평가로 확대하지 않습니다. 요청 리뷰의 범위·한계는 밝히며 같은 세션 검토를 독립 리뷰라고 표현하지 않습니다.

### 학습 설명과 설정

설명은 질문에 충분히 답하되 전체 강의·노트·로그를 복제하지 않습니다. 모델·reasoning·속도를 문서만으로 확인했다고 하지 않으며 런타임 설정·기존 자동화를 임의 교체하지 않습니다. 상시 계측·별도 관리 문서를 추가하지 않습니다.

## 테스트·기록·README

실행·테스트·디버깅은 사용자가 합니다. PM은 요청에 따라 입력·경계 사례·기대 결과를 안내합니다. 예정·정적 확인·사용자 결과를 구분하며 미검증을 완료로 기록하지 않습니다.
단계 상태는 [STATUS.md](STATUS.md), 필수/보너스 충족은 [REQUIREMENTS.md](REQUIREMENTS.md), 실제 중요 이력은 [WORKLOG.md](WORKLOG.md)에 간결히 관리합니다.
README에는 전체 학습 순서·실제 디렉터리·사용 환경을 둡니다. 명령·스크린샷·구조도는 실제 구현과 필요성이 생긴 뒤 추가하며 미실행 명령을 검증된 사용법으로 적지 않습니다. 초기 단계에서 상세 구조도를 만들지 않습니다.

## 학습 문서

상세 노트는 사용자가 원할 때만 단일 `docs/study-note.md`에 단계별로 보완합니다. 초기 chore에서는 만들지 않습니다.
사용자 설계 전에 완성 설계·알고리즘·평가 답안을 채우지 않습니다. 이후 설명을 요청받으면 목표·제약 → 실제 코드 흐름·중간 상태 → 문법·선택 이유 → 예외·복잡도·남은 질문 순서로 설명하고 실제 소스에 연결합니다.
포인터·소유권·수명·해제, LRU·TTL 상태 변화 등 질문에 필요한 개념을 충분히 풀이하되 미구현 소스 링크·함수·라인을 만들지 않습니다. 학습 자료 작성과 이해·실행 검증은 구분합니다.

## 중요한 결정과 반복 피드백

중요 결정만 WORKLOG에 Decision / Reason / Alternative / Why not으로 남깁니다. 변수명 같은 사소한 결정·대화 전체는 복제하지 않습니다.
반복 피드백이 있으면 근거·최소 변경을 제안하고 승인 범위 안에서 관련 문서 한 곳에 통합합니다. 다른 저장소·원본 템플릿에는 전파하지 않습니다.

## Mission Close-out

필수 구현과 사용자 테스트 근거를 확인하고 필수 누락·미검증·선택하지 않은 보너스를 구분합니다. 요청하지 않은 코드 리뷰·별도 평가·리팩터링을 종료 조건으로 추가하지 않습니다.
STATUS·REQUIREMENTS·WORKLOG·README가 실제 결과와 일치하도록 필요한 부분만 갱신합니다. 제출·commit·push는 자동 실행하지 않습니다.

## 새 미션과 세션 복구

공통 Harness 배포본은 새 미션·프로젝트에 재사용하는 기본 시작 구성입니다. 기본 배포에는 공통 지침·역할 프롬프트·빈 미션 기록·TASK/Review/학습 양식만 포함합니다. 기존 프로젝트에 중간 반영하는 병합 안내·패치 파일은 사용자가 명시적으로 요청했을 때만 별도로 만듭니다.

새 미션은 새 repository나 별도 복사본에 공통 지침과 docs/harness/를 배치하고, 미션 원문과 실제 TASK·리뷰·작업·학습 기록이 비어 있는 상태에서 시작합니다. 프로젝트별 기술 스택·특별한 제약만 필요한 만큼 추가합니다. 이미 진행 중인 이 Mini Redis의 원문·상태·이력은 빈 템플릿으로 교체하지 않습니다.

미션 원문과 해석을 분리하고 기존 사용자 변경·기록을 보존합니다. 새 환경에서는 AGENTS·PM 지침 → STATUS → 현재 단계 요구사항·실제 코드 순서로 복구합니다. 과거 이력 전체는 필요한 경우만 확장합니다.
TASK·리뷰·학습 템플릿은 실제 완료 기록이 아니며 미션 진행을 이유로 기존 파일을 초기화하지 않습니다.

## Git·Skill 정책

Git 작업은 [AGENTS.md](../../AGENTS.md)를 따릅니다. 스테이징·커밋은 항상 사용자 직접 수행이며 PM은 실행·권한 요청 없이 함께 이해하고 되돌릴 수 있는 변경에 대한 커밋 권장 범위·메시지 또는 보류 이유만 한 줄 안내합니다. 다른 Git 쓰기는 명시적 요청 경계를 따릅니다. 단계별 커밋을 강제하지 않습니다.
기존 convention을 우선하며 없으면 Chore / Feat / Fix / Refactor / Docs / Test 계열을 참고합니다. 실제 실행하지 않은 commit·SHA·테스트 성공을 기록하지 않습니다. 새 Skill·API·자동 worktree/commit을 추가하지 않습니다.

## 자연어로 이어가기

기존 PM에 질문·사용자 결과·다음 단계 의사를 알려주시면 같은 세션에서 코칭과 상태 기록을 이어갑니다. 역할별 위임·수동 인계·새 PM 생성을 요구하지 않습니다.
